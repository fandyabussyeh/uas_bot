# Bot Dry Run Indodax di Vercel — UAS Algorithmic Trading
Strategi: lihat `STRATEGI.md`. Dry run: semua order disimulasikan terhadap order book publik Indodax; **tidak ada API key, tidak ada uang sungguhan**.

## Struktur
`lib/core.mjs` fungsi sinyal & keputusan (dipakai backtest DAN bot) · `lib/tick.mjs` satu panggilan bot · `api/tick.js` endpoint terlindungi `CRON_SECRET` · `api/export.js` ekspor log · `api/kill.js` kill switch · `api/public.js`+`public/index.html` dashboard Vercel · `scripts/` backtest, hitung_ulang, dashboard offline, snapshot, spread · `tests/test_local.mjs` uji lokal dengan Indodax tiruan · `.github/workflows/tick.yml` penjadwal.

## Langkah (urut)
1. **Persiapan:** Node.js 18+, akun GitHub, Vercel (Hobby), Upstash Redis. `git init`, buat repositori GitHub PUBLIK. Jangan pernah commit `.env`.
2. **Data (laptop):** simpan candle 4H 8 pasangan ke `data/<PAIR>_240.csv` (kolom `time,open,high,low,close,volume`, bar terakhir dibuang bila belum tertutup) dan jalankan `node scripts/snapshot_universe.mjs` terus-menerus (snapshot -> `data/snapshots.jsonl`).
3. `node scripts/make_spreads.mjs` -> `config/spreads.json` (median spread terukur; dibekukan saat freeze). `FEE_TAKER` isi dari /api/pairs & halaman biaya (pakai yang lebih mahal), catat di `STRATEGI.md`.
4. `node scripts/run_report.mjs` -> `out/backtest_out.json` (backtest >=3 tahun). `node tests/test_local.mjs` harus **SEMUA UJI LOLOS**.
5. **Upstash:** buat database Redis; salin REST URL & token. **Vercel:** import repositori; Environment Variables: `CRON_SECRET`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `FEE_TAKER`. Deploy.
6. **Uji koneksi dari Vercel (sebelum freeze):** `curl -H "Authorization: Bearer <CRON_SECRET>" https://<proyek>.vercel.app/api/tick` -> harus mengembalikan JSON `status: processed` (atau `duplicate`). Jika Indodax tidak bisa diakses dari Vercel, laporkan ke dosen sebelum freeze.
7. **GitHub Actions:** Settings > Secrets: `CRON_SECRET`, `TICK_URL` (= `https://<proyek>.vercel.app/api/tick`). Workflow memanggil menit ke-7 dan ke-22 tiap candle 4H (panggilan kedua idempotent).
8. **FREEZE:** baseline strategi `519e62f` (commit "Record UAS strategy freeze baseline") pada 2026-11-07 07:56 WIB; keputusan jendela 7 hari dicatat pada `95db09e`. Smoke test koneksi manual pukul 07:35 WIB (status `processed`) mendahului freeze; **forward test disepakati 7 hari** (soal meminta 10 hari — lihat langkah 9), dihitung dari pemanggilan cron terjadwal pertama setelah freeze. **Jangan ubah aturan/parameter/universe, jangan force-push.** Bug fix yang tidak mengubah aturan dicatat.
9. **Forward test:** soal meminta 10 hari; untuk tenggat 14 Nov disepakati 7 hari. Catat sebagai deviasi dan jangan klaim 10 hari. Mulai hitung dari tick cron pertama yang berhasil setelah reset state. Kill switch: `curl -H "Authorization: Bearer <CRON_SECRET>" "https://<proyek>.vercel.app/api/kill?on=1"` (matikan dengan `on=0`); tercatat di log.
10. **Akhir:** `curl -H "Authorization: Bearer <CRON_SECRET>" https://<proyek>.vercel.app/api/export > out/logs.json`; unduh candle 4H sampai akhir jendela ke `data/`; `node scripts/hitung_ulang.mjs out/logs.json` -> `out/hasil_forward.json`; `node scripts/make_dashboard.mjs` -> `out/dashboard.html` (offline). Tulis refleksi di dashboard.

## Catatan operasional pasca-freeze (TIDAK menyentuh aturan, parameter, atau universe)

Dicatat sesuai ketentuan soal bahwa perbaikan operasional/infrastruktur boleh dilakukan tanpa mengubah aturan, asal tercatat.

- **8 Nov 2026 — keandalan penjadwal.** Riwayat publik Actions menunjukkan beberapa fire terjadwal GitHub tidak dieksekusi/telat berat (mis. fire 04:07/04:22, 12:07/12:22 UTC 7 Nov hilang -> candle bar 08:00 UTC tidak diproses; fire 00:07/00:22 UTC 8 Nov jauh melewati 11.00 WIB). Dampak diukur lewat `lateSec`/uptime pada log. Memperbaiki: satu **penjadwal cadangan independen** `.github/workflows/tick_backup.yml` (jalankan jam :37 & :52 UTC tiap candle 4H, memakai secret `CRON_SECRET` + `TICK_URL` yang sama di tingkat repositori) — file dipisah dari `tick.yml` agar GitHub tidak membatalkan keduanya bersamaan, dan panggilan ganda otomatis jadi "duplicate" (idempotency). Aturan strategi, parameter, universe, dan basis kode sinyal (`lib/core.mjs` dkk) **tidak diubah**; commit ini + README ini adalah catatannya. Repositori juga dijadikan publik (`visibility: public`) agar riwayat commit — termasuk commit freeze `519e62f` — bisa diaudit.
- **Artefak statis di luar repo (git-ignored / untracked).** `data/universe.json` (root repo, peringkat volume mentah dari `step2_universe.mjs`) kini **stale**: memuat VELOIDR, sedangkan universe beku sesuai `config/universe.json` adalah BTCIDR, XRPIDR, ETHIDR, DOGEIDR, TRXIDR, BNBIDR, ADAIDR, SOLIDR (VELO gugur filter spread; berlaku `config/`). Berkas itu tidak dipakai kode; versi terbaru output `step2` ada di `seleksi_universe.csv` (repo root, untracked). Hasil beku acuan: `config/universe.json` + commit freeze.
- **8 Nov 2026 (lanjutan) — penjadwal lokal.** Fire cadangan `tick-backup` (12:37/12:52 UTC) juga tidak dieksekusi GitHub; total 0 run baru 06:17–13:21 UTC. Menambah **penjadwal lokal** `scripts/tick_local.ps1` (Windows Task Scheduler, task `UAS_bot_tick`, tiap 4 jam menit ke-7 WIB) yang memanggil `/api/tick` dengan secret dari `.env` lokal (gitignored, tidak ikut dikumpulkan). Task ini pelengkap, bukan pengganti: fungsi bot tetap di Vercel, penjadwalnya bisa apa pun yang memanggil endpoint. Aturan/parameter/universe tetap tidak diubah.
- **10 Nov 2026 — rotasi `CRON_SECRET` (perbaikan operasional).** Kunci lama tidak dapat dilihat ulang di Vercel, maka diganti dengan nilai baru yang identik di 3 tempat: Vercel (Environment Variables, lalu Redeploy), GitHub Actions secret `CRON_SECRET`, dan `.env` lokal untuk `tick_local.ps1`. Nilai kunci tidak dicantumkan di repositori/dokumen ini (hanya di environment variable). Task lokal diset agar tetap jalan saat pakai baterai dan langsung mengejar jadwal yang terlewat (`StartWhenAvailable`). Aturan/parameter/universe tidak diubah.
- **Template dashboard.** `scripts/dashboard_template.html` sempat mencantumkan hash freeze `466bf39`; dibetulkan menjadi `519e62f` (2026-11-07 07:56 WIB) — arsip terpasang lagi benar.
